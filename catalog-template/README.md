# Raphael member catalogue

## Opening the store: the two steps that are the owner's

Until both are done the store in Raphael says "The store is not open yet" and asks the network for nothing:
`PUBLIC_KEYS` in `core/src/raphael_core/members/member_catalog.py` is empty, and no key is generated or kept by Raphael or by this repository.

1. **Create the catalogue repository.** Make the public repository `Jheng-Kai/raphael-catalog` on GitHub (or another HTTPS root, see
   `RAPHAEL_CATALOG_URL` below) and copy this directory into it. Turn on branch protection for `main` that requires the validation
   check and a human review, and let only the signing identity publish `index.json.sig`.
2. **Generate the signing key, once, outside this repository.** Make an Ed25519 key pair. Put the private half (the base64 of its raw
   32-byte seed) in that repository's secret `CATALOG_SIGNING_KEY`. Put the public half (64 lowercase hexadecimal characters, the raw
   32 bytes) in `PUBLIC_KEYS` of `member_catalog.py`, then ship a Raphael release. Add a second public key there only while a key is being
   rotated (see below). A value that is not 64 hexadecimal characters is refused when the store is made, so a typo can not pass for a key.

Then publish the first signed index (`python scripts/sign.py`, run by the repository's workflow on a push to `main`) before the release
that carries the key goes out: a store with a key and no signed index shows "offline" until it exists.

Copy this directory into the owner-created public `Jheng-Kai/raphael-catalog` repository.
The catalogue uses Raphael's existing `.raphael-member` v1 format; never add private
memory, credentials, permissions, images or model choices. Packages live at
`packages/<id>/member.raphael-member`, beside a README identifying creator and license.
Add the entry, exact SHA256, counts, category, existing slime character and dates to
`index.json`; increase `sequence` on every edit. Deletions also permanently add the ID
to `revoked`. Review full instructions and skill dependencies for prompt injection.
The scanner is a heuristic, not a guarantee of safe content.

Run `python scripts/validate.py` before opening a PR. PR CI has no signing secret.
Only a validated main-branch push can sign. Configure branch protection requiring
validation and human review; permit the signing identity to publish the signature.
The default raw GitHub URLs can briefly expose an unsigned merge while signing runs;
clients refuse that mismatch and retry on the next owner-requested refresh.

The key is made as the second step above. No production private key is shipped or generated by Raphael.
The checked-in signed synthetic fixture uses a separate, discarded private key and
is never a production trust root. Publish the signed initial index before launch.

For rotation, first ship a Raphael release accepting the old and new public keys,
then change the signing secret, and remove the retired public key in a later release.
Never reset sequence or remove revoked IDs. An owner may select another HTTPS root
using `RAPHAEL_CATALOG_URL`; the compiled trust roots remain mandatory.

Publishing from Raphael prepares a local package and opens a prefilled compare/PR
page. The owner forks the catalogue, uploads the package and README, adds an index
entry and submits the PR using GitHub's own login. Raphael stores no GitHub token.
Update an entry through another reviewed PR; removal requires its permanent revoked ID.
